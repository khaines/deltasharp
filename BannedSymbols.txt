// DeltaSharp banned-API policy. Each entry is a documentation-comment ID followed by
// ";[category] remediation". Categories cover dynamic-code/AOT, trim/AOT, determinism, and
// security-sensitive APIs. Name-only method IDs match only the parameterless overload, so
// dangerous overloads are listed explicitly. BannedApiAnalyzers silently ignores any line it
// cannot resolve (no diagnostic), so a mistyped documentation-ID is a no-op — keep IDs exact
// and prove new bans actually fire. Scoped, justified exceptions go through a
// "#pragma warning disable RS0030" linked to ADR-0001 or ADR-0014 — see
// docs/engineering/design/api-governance.md.

// === Determinism: ambient state breaks reproducible planning, caching, and tests ===

P:System.DateTime.UtcNow;[determinism] DateTime.UtcNow reads the wall clock and is nondeterministic. Inject a TimeProvider/clock so query planning, retries, and tests are reproducible.
P:System.DateTime.Today;[determinism] DateTime.Today reads ambient local time and is nondeterministic. Inject a TimeProvider/clock and use UTC.
P:System.DateTimeOffset.Now;[determinism] DateTimeOffset.Now reads ambient local time and is nondeterministic. Inject a TimeProvider and use UTC.
P:System.DateTimeOffset.UtcNow;[determinism] DateTimeOffset.UtcNow reads the wall clock and is nondeterministic. Inject a TimeProvider/clock.
M:System.Guid.NewGuid;[determinism] Guid.NewGuid is a nondeterministic identity source. Inject an id/RNG abstraction so plan, shuffle, and file identifiers are reproducible and testable.
T:System.Random;[determinism/security] System.Random is banned outright: it is not thread-safe and an unseeded instance is nondeterministic. // === Direct ILogger exception-object logging: ban the LoggerExtensions.Log*(…, Exception, …) overloads +
// the hand-written LoggerMessage.Define back door ===
// (#810, extends #694 and the #455 telemetry-scrubbing family.) The storage logging-hygiene guard
// StorageLogSites_NeverAcceptAnExceptionObject (#694) proves the repo's [LoggerMessage] SOURCE-GENERATED
// log sites never accept an Exception parameter — so a sink that renders OR destructures the exception
// cannot re-leak the tenant-bearing paths DeltaSharp's exception types deliberately scrub. (DeltaSharp's
// ToString() overrides drop the inner chain but RETAIN the raw inner, reachable via InnerException — so a
// structured/JSON sink that walks .InnerException/.StackTrace/.Data recovers exactly what the scrubbing
// ToString() hides; a plain ToString()-rendering sink gets the safe form. The object hands over the whole
// exception either way.) That reflection sweep is, by design, scoped to [LoggerMessage]-decorated methods
// and is BLIND to a direct logger.LogError(ex, …) / LogWarning(ex, …) / Log(level, ex, …) call, or a
// hand-written LoggerMessage.Define/DefineScope delegate (trailing Exception?), placed anywhere in a
// production assembly — each hands the exception object to the sink, exactly the class already banned for
// telemetry (Activity/TelemetrySpan.RecordException, #455).
//
// Bans below: every exception-taking LoggerExtensions overload (RS0030 at the call site). There are ZERO
// direct call sites today (every production log site is [LoggerMessage] source-gen), so the bans have zero
// migration cost. What they push toward is logging via [LoggerMessage] sites carrying only bounded/structural
// fields (exceptionType string, kind — the DeltaVacuumLog / StorageLogSiteSignatures precedent), never the
// raw exception object.
//
// RESIDUAL, deliberately NOT symbol-banned (both are what the [LoggerMessage] source generator itself emits,
// so a symbol ban would fail the build on the GENERATED code — verified: a type-ban on LoggerMessage trips
// RS0030 inside LoggerMessage.g.cs — and there is no way to ban the human-written call without also banning
// the generator's own use): (1) the core primitive
// ILogger.Log<TState>(LogLevel, EventId, TState, Exception?, Func<…>); and (2) LoggerMessage.Define /
// DefineScope, whose returned delegates take a trailing Exception?. A hand-written call to either hands the
// exception object to the sink and is invisible to the #694 sweep (neither is [LoggerMessage]-attributed).
// These stay closed by the zero-direct-call-site convention (all logging is source-gen [LoggerMessage]); a
// future BODY-LEVEL guard (like the telemetry TelemetryExceptionScrubbingGuardTests source scan) could assert
// no production body passes a non-null exception to Log<TState> or builds a LoggerMessage.Define delegate — a
// follow-up beyond this symbol-ban's scope. (3) The message-side leak (a $"{ex.Message}" hole reaching a
// LoggerMessage template) is a distinct concern pinned by the storage message-hygiene guards.
//
// The reflection guard BannedSymbols_BanEveryExceptionTakingLoggerExtensionsOverload proves the 14 bans
// resolve (BannedApiAnalyzers silently ignores an unresolvable ID) and fails loudly if a future
// Microsoft.Extensions.Logging version adds a 15th exception-taking overload. RS0030 has NO exemption —
