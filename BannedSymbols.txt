// DeltaSharp banned-API policy. Each entry is a documentation-comment ID followed by
// ";[category] remediation". Categories cover dynamic-code/AOT, trim/AOT, determinism, and
// security-sensitive APIs. Name-only method IDs match only the parameterless overload, so
// dangerous overloads are listed explicitly. BannedApiAnalyzers silently ignores any line it
// cannot resolve (no diagnostic), so a mistyped documentation-ID is a no-op — keep IDs exact
// and prove new bans actually fire. Scoped, justified exceptions go through a
// "#pragma warning disable RS0030" linked to ADR-0001 or ADR-0014 — see
// docs/engineering/design/api-governance.md.

// === Determinism: ambient state breaks reproducible planning, caching, and tests ===
P:System.DateTime.Now;[determinism] DateTime.Now reads ambient local time and is nondeterministic and time-zone dependent. Inject a TimeProvider/clock and use UTC so planning, caching, retries, and tests stay reproducible.
P:System.DateTime.UtcNow;[determinism] DateTime.UtcNow reads the wall clock and is nondeterministic. Inject a TimeProvider/clock so query planning, retries, and tests are reproducible.
P:System.DateTime.Today;[determinism] DateTime.Today reads ambient local time and is nondeterministic. Inject a TimeProvider/clock and use UTC.
P:System.DateTimeOffset.Now;[determinism] DateTimeOffset.Now reads ambient local time and is nondeterministic. Inject a TimeProvider and use UTC.
P:System.DateTimeOffset.UtcNow;[determinism] DateTimeOffset.UtcNow reads the wall clock and is nondeterministic. Inject a TimeProvider/clock.
M:System.Guid.NewGuid;[determinism] Guid.NewGuid is a nondeterministic identity source. Inject an id/RNG abstraction so plan, shuffle, and file identifiers are reproducible and testable.
T:System.Random;[determinism/security] System.Random is banned outright: it is not thread-safe and an unseeded instance is nondeterministic. Inject a deterministic RNG abstraction (seeded at a well-defined point) so shuffles and sampling are reproducible. For security-sensitive randomness use System.Security.Cryptography.RandomNumberGenerator.
P:System.Environment.TickCount;[determinism] Environment.TickCount reads the ambient system uptime clock and is nondeterministic. Inject a TimeProvider/clock so timing-dependent logic stays reproducible and testable.
P:System.Environment.TickCount64;[determinism] Environment.TickCount64 reads the ambient system uptime clock and is nondeterministic. Inject a TimeProvider/clock so timing-dependent logic stays reproducible and testable.

// === Telemetry tenant-scrubbing: an exception recorded onto a span/Activity captures its raw
// exception.message as a span attribute, and DeltaSharp diagnostics deliberately name the resource
// (AnalysisException.TableOrViewNotFound embeds the table identifier; SinkDescriptor/EXPLAIN render
// table=<identifier>) — so recording one onto a span would move a tenant-bearing identifier into
// telemetry, which the observability conventions require to be scrubbed/omitted at that boundary
// (#455; checklists 09a/14). No telemetry export is wired yet (there are ZERO call sites today), so
// this ban has no migration cost; it forces the future telemetry code to consciously redact/omit the
// identifier and emit a bounded STRUCTURAL form (never the raw exception/message) instead of blindly
// recording the raw diagnostic. RS0030 has NO exemption here — the sanctioned path is a bounded tag,
// not a pragma'd raw record (the SqlParseException-ctor precedent, #687); the sibling value-side leak
// (SetTag/SetStatus/AddEvent with .Message/.SimpleString, or an "exception.message" tag key) cannot be
// symbol-banned and is pinned by TelemetryExceptionScrubbingGuardTests instead. This does NOT change the
// safe/unsafe rule for Exception.ToString() chain-walking (#749) — it is the distinct "message carries a
// tenant identifier" concern. The two OpenTelemetry entries are FORWARD bans (dormant until
// OpenTelemetry.Api is referenced; both overloads are already [Obsolete] in favor of Activity.AddException,
// which is the durable sink). See observability-conventions.md. ===
M:System.Diagnostics.Activity.AddException(System.Exception,System.Diagnostics.TagList@,System.DateTimeOffset);[security] Activity.AddException records the exception's raw message as a span attribute; a DeltaSharp diagnostic (AnalysisException, EXPLAIN/SinkDescriptor) can embed a tenant-bearing table/catalog identifier, so recording it onto a span leaks that identifier into telemetry (#455; checklists 09a/14). Scrub/omit the identifier and emit a bounded structural tag instead; RS0030 has NO exemption — do not pragma a raw record.
M:OpenTelemetry.Trace.ActivityExtensions.RecordException(System.Diagnostics.Activity,System.Exception);[security] Activity.RecordException auto-captures exception.message onto the span; a DeltaSharp diagnostic can embed a tenant-bearing identifier, so this leaks it into telemetry (#455; checklists 09a/14). Scrub/omit and emit a bounded structural tag instead; RS0030 has NO exemption. (Forward ban: resolves once OpenTelemetry.Api is referenced; [Obsolete] in favor of Activity.AddException.)
M:OpenTelemetry.Trace.ActivityExtensions.RecordException(System.Diagnostics.Activity,System.Exception,System.Diagnostics.TagList@);[security] Activity.RecordException(ex, tags) auto-captures exception.message onto the span; a DeltaSharp diagnostic can embed a tenant-bearing identifier, so this leaks it into telemetry (#455; checklists 09a/14). Scrub/omit and emit a bounded structural tag instead; RS0030 has NO exemption. (Forward ban: resolves once OpenTelemetry.Api is referenced; [Obsolete] in favor of Activity.AddException.)
